Media Map - 2021

I built the Media Map project in 2021 as part of Columbia University's User Interface Design class. The guiding concept was that of a site that could recommend media on the user's terms. Existing media-finding applications like Netflix or Disney+ use opaque algorithms based on the user's watch history.

Media Map returns agency to the user. The program would create "links" between different film and television titles. Users could then use those specific, named connections as the criteria for their algorithmic recommendations.

Sometimes you want the same genre. Other times, the same actor. Other times, the same mood. Media Map lets users decide.

What if users could choose their own categories as specific as "swoonworthy romantic TV comedies" or "supernatural movies"?

There are two sections on this page: the mid-semester Individual Project, where I originated the idea, and the semester-end Group Project, where I collaborated with three other students to develop the design further.

Individual Project

Media Map started as my mid-semester individual project, which I took through 4 (and a half) design loops.

LOOP 1 (CONCEPTUAL):

Biggest Risk: Finding a legitimate need.

Design: I began with needfinding via contextual inquiry. I had two users take me step-by- step through their media-finding processes, and perceived a need for convenience - my users switched between websites to find, learn about, and access media. In response, I developed two design solutions, created two personas, and made storyboards of their user journeys. I decided on a design: a hub to concentrate media recommendation, info-gathering, and analysis.

Evaluation: From teacher feedback, I was told that the novelty of my proposed solution was the concept of cross-media recommendations: recommending books based on movies and vice versa. I changed my target audience. From TA feedback, I was told that the design combined functionalities without innovating. I added a new functionality: a "content map" visualizing links between media titles.

LOOP 2:

Biggest Risk: User interest. Now that I have a design, is it helpful to users? Does it solve the problem?

Design: I used the results of Loop 1 (needfinding, storyboards, personas) to create a design, focusing on Nielson's usability heuristics and consistency with similar existing platforms.

Prototype: I made a detailed, low-fidelity paper prototype. The moving parts simulated a website. It was a horizontal, breadth-based prototype: creating many pages so users could interact with many features, rather than developing one feature in detail.

Evaluation: I did three user studies with the paper prototype. I asked users to do specific tasks and explore while providing think-aloud comments, then interviewed them about their experiences.

The result was that users did not want to change their media-finding habits: the inconvenience was not great enough for them to change. What interested them, instead, was my last-minute addition of a "content map", which solved a hidden problem. They did not want multi-source recommendations, but explainable, controllable recommendations.

LOOP 3:

This loop introduced a new problem statement: Users want understanding and control over their algorithmic media recommendations, but existing solutions do not provide a way to get this.

Biggest Risk: Fully solving the user problem. I needed to know what recommendation options users wanted before I could determine which ones to provide. (For example--should they get many diverse options, or only a few broadly-desirable ones?) In addition: usability. The site must be visualized clearly to allow users to understand and control their recommendations.

Design: I developed a design to provide users with a “content map.” This “map” would show users what connections existed between different types of media and allow them to choose which connections they wanted to use to find recommendations. In order to mitigate risks, I created seven possible designs. This would allow me to check which designs were the best at solving the user problem in a way understandable to users.

Prototype: I created a non-interactive paper prototype showing my seven possible designs. The paper prototypes were not interactive due to time constraints. When creating the seven possible designs, I mixed my preferred format — a network-like visual map — with other potential designs, including a row-based format similar to that of Netflix and a vertical-column-based format. By mixing these designs, I would see what format users preferred without bias. I also created a list of possible criteria which users might be interested in when getting media recommendations.

Evaluation: I showed my paper prototype to three users, and verbally described the user flow. One user, an avid Netflix user, liked the familiar Netflix-like format. The other two users preferred the more-interesting map-style format. Putting my users' feedback in context, I went ahead with the map-style format: Netflix fans would likely continue using Netflix. Next, I asked users what they thought of the potential links between different media titles. The users indicated that they preferred to have as many potential links as possible. They valued flexibility and control over a simple interface.

LOOP 4:

Biggest Risk: Usability, in a more advanced way. If users could not intuitively understand and navigate the format I chose, the product would not be helpful.

Design: I made my design of the content map more detailed, and created new storyboards to describe the user flow. This was to help me understand how users would interact with the site, and from there make the site easy to use.

Prototype: I created two more-detailed non-interactive paper prototypes. Again, these prototypes were not interactive due to time constraints. These prototypes demonstrated two separate user flows. One was a more complicated (but more flexible) method for the user to choose what links would be shown on the map. The other was simpler (but more restrictive.)

Evaluation: I showed my prototypes to two users and explained their respective user flows. The users felt that the overall design was understandable. One user suggested a design with even more flexibility than my own, but the other user preferred the more simple design.

LOOP 5:

Biggest Risk: Big-picture, overall functionality. Was my site a holistic, useful, and interesting website? Was the detailed design unified and understandable?

Design: Using the user feedback from Loop 4, I improved the usability of my website by turning my more-complicated design into a path for expert users. Most users will see only the more simple design, but I added an “advanced options” button which gives experts a way to further personalize their content map. In response to the biggest risk of this loop, I created an even more detailed design for my content map to enable me to see the whole of my website.

Prototype: I created a high-fidelity prototype of my site in Figma. This detailed design let me see how the website looks as a whole.

Evaluation: There is no evaluation portion to this loop. This is where the Individual Project ends.

Group Project

The group project followed directly from my individual project. We updated the storyboards to reflect the direction of the project.

We developed five low-fidelity Balsamiq prototypes and conducted sixteen (16) user interviews.

Following the user interviews, we created an updated low-fidelity protoype and performed thirteen (13) additional interviews.

Afterwards, we created a high-fidelity prototype in Figma.

We also created a high-fi prototype using HTML/CSS/JS. (Due to the limits of the implementation, only a single use case is doable; see the Site Instructions text file for the specific set of actions you can do.)
